Specification: the approved `docs/development-plan.zh-CN.md` D16 and continued implementation request. Offline operational commands only; no renderer file authority or real chat/provider operations.

## Design and rulings

- Use a private UUID directory, fixed component names and a versioned strict manifest published last. Every present file has size/SHA-256 and each SQLite component has an independently consistent native backup with integrity/schema checks. Optional device/legacy/foreground sources have explicit absence records; required sources cannot be silently omitted.
- Central source is a full custom-format `pg_dump`, without table/data filters or row-security partial exports. Use environment credentials, never arguments/report content; failed/warning/partial export cannot publish a successful bundle. Verification uses offline `pg_restore --list` as well as component digests. PostgreSQL documentation: https://www.postgresql.org/docs/16/app-pgdump.html and https://www.postgresql.org/docs/16/app-pgrestore.html.
- Ruling: this is a collection of independently consistent component snapshots, not a distributed point-in-time transaction — PostgreSQL and employee SQLite do not share one transaction. Record the capture interval and this limitation. Restoration remains quarantined; do not infer missing post-backup messages from this archive.
- Restore only to a new directory. Preserve the exact config/device/learning/central bytes in a `review-only` staging directory, never install them as an active employee profile or execute central SQL. Restore ledger through its existing provenance/fence routine. Publish a non-activating staging receipt last; partial targets remain unavailable and are never overwritten.
- Ruling: old automatic settings, active learning revisions and machine-encrypted credentials are historical material, not restored authority — prevents background sends before central account/history review. Operational staged recovery is distinct from final administrator PostgreSQL activation and guarded profile installation, which remain pending D16 work.
- Preserve coauthor learning changes, current branch and all existing security gates. No shared commits, production writes, permission reminders or new physical readiness requests.
