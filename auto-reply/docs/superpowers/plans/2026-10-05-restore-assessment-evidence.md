# D16 统一恢复依据与外部证据引用

沿用用户已经授权的 D00–D20 开发计划，直接在当前分支执行。本增量接通管理员审批所需的完整依据和证据历史；后续决定、本地应用、中央确认及真实验收继续保留，不能把引用证据当作已经证实事实。

## Design

独立管理员在既有账号锁内读取一份完整已接收清单和全部开单/当前中央许可，不通过循环分页重复验证。依据包含恢复来源、完整清单收据、当前账号/设备/租约状态、所有本地条目及中央许可。即使显示第一页，摘要和统计仍覆盖全部记录；换页要求原依据摘要，晚到结算、设备变化或源损坏拒绝旧依据。

核对对象分为账号停止情况、本地消息历史、本地执行和中央执行。每项返回明确的事实缺口，中央存在而恢复副本没有的许可也纳入。管理员可追加仅含引用 ID、文件摘要、观察时间和具体对象摘要的外部证据记录；绑定 case/upload/依据/对象，不保存正文、图片、路径或凭据。不同租户/账号、普通员工、错误类型、旧依据、未来观察时间及同 ID 改内容均拒绝。相同请求重试返回原历史记录，证据和审计同一事务，旧依据记录仅供历史查询。

所有结果保持 canRelease=false。引用和摘要是管理员提交的元数据声明，真实性和充分性仍须后续独立决定审核；不会修改 unknown、水位、许可或暂停，不增加恢复启用按钮。协议和依据先完成，后续恢复授权必须明确使用它们，不能另造较弱入口。

## Review Focus

- 中央备份后新增而本地不存在的许可不得遗漏。
- 第一页不能产生只覆盖第一页的摘要；末页变化必须使旧依据失效。
- 同 ID 重试不能变成新的事实，旧历史重试不能被误称为当前依据有效。
- 外部引用类型必须匹配实际核对对象，证据本身不授予发送权。
- 普通服务角色和未启用管理员不能记录或读取；审计失败不能留下证据。
