## Design decisions

- Restore only a verified, private bundle into a newly generated `autoreply_restore_<UUIDhex>` database. Create with `ALLOW_CONNECTIONS=false`, remove PUBLIC database privileges and verify no ordinary login has CONNECT before allowing the maintenance owner to connect. Never import into, clean, rename or replace an existing database. Failed attempts remain restricted; no automatic cleanup of an unknown database.
- Use fixed `pg_restore --single-transaction --exit-on-error --no-owner --no-privileges --no-password` arguments against the generated database. Maintenance credentials only in environment; no SQL/credentials in reports. Only internally produced trusted backups may be imported. Current cluster must already have the trusted service role definitions; do not replay global cluster roles/passwords from an archive.
- After import, a migration-owned transaction records new central restoration provenance, pauses every account, revokes all still-active old devices, expires leases and unused enrollment codes. Preserve published config/knowledge/learning, previous audits, all send records, unknown results and their original identities. Append audit events; never convert issued/unknown history into successful deliveries.
- Database triggers prevent any ordinary/administrator code from resuming an account, creating a live lease or issuing a permit while central restoration is pending. Guard owner must retain privileged migration identity; degraded/corrupt history fails closed. Marker is append-only and carries the complete prior chain plus archive binding. No release route/flag is accepted in this increment.
- Ruling: database quarantine is a server-side stop fact, not proof of physical stops or complete post-backup history. Formal activation/cutover still requires the original device/history/business checks. Keep DB CONNECT restricted and return `canRelease=false`/`automaticStart=false`; staged recovery is reviewable but does not grant production activation.
- Ruling: frozen private archive copy inside a new protected operation directory prevents source replacement between bundle verification and import. Manifest-last success receipt; failed/partial directories and databases retained for diagnosis without a completion receipt.

Caller supplies an idle maintenance connection; the function owns its transaction, validates current database/privileged owner and prior immutable provenance, captures complete counts, appends exact new metadata, updates only authentication/control columns and audits. Generates database name itself and produces bounded non-activating receipt. `scripts/central-recovery.ts restore --backup DIR --output NEWDIR [--pg-bin DIR]` uses maintenance connection environment only.
