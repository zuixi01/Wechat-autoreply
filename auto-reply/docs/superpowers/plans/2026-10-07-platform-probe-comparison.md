## 实现

新增 `probe:compare --control UUID --raw UUID`，只读取既有私有探测目录中的严格合同证据，单份最多 4MiB，不接受任意文件路径。保存新的私有 `comparison.json`，绑定源文件原字节 SHA-256，不修改输入。

报告比较成功状态、控件视图角色、窗口实例、客户端/Windows/辅助完整版本、发布编号/清单及采样时间。快照 ID 不得复用，间隔五分钟内才输出数量差异；这只是比较范围，不保证同一业务状态。截断与活动不可用仍保留原原因。原始客户标识、runtime ID、类名、句柄和进程启动 ticks 不进入输出；只汇总白名单的声明模式。raw 非控件数不等于“同一个消息树新增节点”。模式存在不证明能读文字或后台发送，零模式不证明平台永远不可读。

CLI 不启动原生辅助、不枚举微信/企微、不调用模型、没有发送动作。输出所有能力 false、消息/模型 0、`snapshotsMerged/nodeIdentityMatched=false`。失败可比较条件保存原因并退出 2；参数/私有文件等错误退出 1；成功汇总退出 0。

## 项目盘上发现的实际故障

临时 CLI 夹具首次在 E 盘创建空目录后，私有 ACL 初始化失败。只读检查确认 NTFS 正常、目录归当前用户、继承权限为 Modify。对已属于当前用户的目录重复调用 SetOwner，仍请求 WRITE_OWNER；所有者可控制 DACL，但没有必然获得 WRITE_OWNER，见微软 [所有者权限](https://learn.microsoft.com/en-us/windows/win32/secauthz/owner-of-a-new-object) 与 [标准访问权限](https://learn.microsoft.com/en-us/windows/win32/secauthz/standard-access-rights)。

修复共享 `protectPrivateDirectory`：先验证当前所有者，保持所有者不变，只写入当前用户和 SYSTEM 的保护 DACL，随后沿用完整核验。拒绝非当前所有者目录，不接管所有权，不使用管理员提权或公开输出。既有读取/文件 ACL 校验不变。

新增真实 Windows 权限回归：当前用户拥有目录，允许 Modify、明确拒绝 TakeOwnership，证明旧的重设所有者调用失败，再验证修复后的保护与子文件私有读取成功。实际项目盘合成命令亦完成输出 ACL 往返，解决临时目录测试遗漏的权限差异。
