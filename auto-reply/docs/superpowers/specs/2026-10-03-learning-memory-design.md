# 工作记忆持续学习设计

用户授权：按 2026-10-03 聊天中的完整七步计划执行，包含本地与企业回复、自动学习和迭代、界面及效果评测。不是只增加经验卡片。完整目标保持到所有验收项取得证据。

## 目标和架构

移植 Hermes 266f11c 的分层记忆、案例检索、后台复盘、技能修订、整理机制，使用现有 TypeScript 和模型客户端。学习独立于回复发送。持久化的学习任务在空闲执行，允许没有新经验。来源案例和人工反馈产生候选版本，验证与发布使其生效，后续反馈驱动修订、合并、归档及恢复。

本地 SQLite 为个人学习权威，企业 PostgreSQL 为企业正式记忆权威。共享 Zod 合同和纯逻辑，不引入 Python 运行依赖。复用中文分词，先验证全文检索，不默认引入向量服务。数据库是权威，技能 Markdown 可作为导出格式。企业学习变更必须绑定现有不可变发布、生成缓存和评测准入，不能通过设备提交直接改变企业规则。

## 数据与约束

- MemoryScope：workspaceId（本地安装配置标识），platform，tenantId/accountId（企业模式必须同时存在），conversationId（客户专属；使用可信 ID，不用显示名）。共享经验必须经单独的泛化流程。
- Episode：问题处理片段；sourceId 幂等，入站/草稿/人工修改/结果/反馈和时间；同客户不同问题可多个片段。不得以一次全局引擎 session 作为单客户身份。
- Memory：preference/lesson/skill，场景、处理步骤、例外、验证、原因、来源案例。每次修订不可变，内容哈希，expectedRevision 乐观锁，旧版本可恢复；pending/active/stale/archived/forgotten 状态。客户原话是数据，不是全局指令。
- 学习模式 off/suggest/auto；初始 suggest。用户可切换，auto 只激活通过验证且在允许类型范围的候选。事实知识由知识库负责，学习不得捏造事实、修改发送权限、审批政策或收件人。
- 单轮检索最多 5 条、上下文初始预算 2000 tokens（没有对应 tokenizer 时保守估计，并明确计量方法）；按作用域、状态、有效期过滤后排序。每轮固定版本快照。
- 学习队列并发 1，持久化、幂等、合并未执行片段、取消、超时、重试上限、token 日预算；前台优先。学习失败不阻断正常回复，记忆读取失败不伪造可用结果。
- loaded/modelReported/adopted/substantiallyCorrected/deliveryConfirmed/factError 等分开计量；模型声明采用不等于因果证据，未知发送不等于成功。
- 明确遗忘阻止旧案例重新提取已忘内容，保留最小 tombstone。删除客户时覆盖案例、索引、反馈、任务及其派生经验，处理备份保留说明。
- 旧 cards.json 只读备份、幂等迁移。未知归属进入待整理；旧使用统计只标记 legacy，不能当新质量指标。
- 定期整理仅自动学习内容；固定的人为规则不自动改动；合并保留原证据，归档可恢复。

## 验收

1. 跨企业/账号/同名客户隔离，案例证据可追溯。
2. 迁移、重启、写入故障、重复事件可靠，无虚假保存成功。
3. 人工纠正和片段结束自动产生学习任务；模型失败正常回复继续，重启可恢复。
4. 中文询价/投诉场景相关检索，最多 5 条，预算有界，无关卡片不注入。
5. V1→反馈→V2→对照回放→发布/回退完整演示，并发修订不互相覆盖。
6. 本地和企业生成实际使用记忆并展示版本，旧缓存不能跨新版本复用。
7. 界面可查看案例、候选差异、任务、成本、使用及质量指标，支持模式、固定、停用、归档、恢复、遗忘。
8. 冻结 A无记忆/B旧卡片/C新机制，在会话级分离学习/校准/留出集，真实人工标签评测。合成测试证明工程行为，不证明业务改善；无真实标注不能宣称完整效果验收。
