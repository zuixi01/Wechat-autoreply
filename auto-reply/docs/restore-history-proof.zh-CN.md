# 恢复历史证据验证

恢复旧账本后，备份中的清单不能证明备份之后没有新消息或新发送。新增验证器为最终恢复批准准备独立历史来源的输入；当前没有注册任何生产历史来源，也没有开放恢复批准或自动启动。

## 合同与检查

独立来源持有 Ed25519 私钥，签署固定用途和完整规范化报告摘要。服务端单独配置来源公钥、企业/账号/平台及平台账号摘要、版本/发布摘要、实机历史能力验收摘要和有效时间；报告不能携带自己的信任配置。使用 Node 24 的 [crypto.verify](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoverifyalgorithm-data-key-signature-callback)，拒绝不同算法、未知来源、撤销/过期配置及错误签名。

报告绑定恢复编号、上下文、核对单、上传编号和完整清单摘要，包含账号会话清单、每会话的完整性/缺页标志以及消息源 ID、方向、内容摘要、位置和时间；不包含正文。核对完整恢复清单的全部行及统计，不能只传员工界面的一页。需要已核实的账号/消息身份，不按显示名称猜测映射。每个执行记录对应的会话也必须出现，包括该会话在备份中没有消息的情况。相同平台消息在历史登录轮次中重复出现时只计一个锚点，各份本地内容和方向仍须分别匹配。

覆盖起点必须不晚于可信维护记录中的备份**开始时间**，观察终点必须覆盖独立核实的全部设备停止时间。备份 manifest 的 createdAt 是快照发布后记录时间，不能当作备份开始时间，否则会漏掉快照和发布之间的历史。可信维护起点或设备停止事实缺失时，后续管理员流程不得构造一个猜测时间通过检查。本增量没有为旧备份凭空补齐这些事实。

捕获及观察记录必须在检查时间五分钟内，来源在捕获和检查时都有效。这是当前证据接收范围，不证明客户端稳定或期间物理静止。拒绝重复会话/消息 ID、位置不连续、声明缺页/缺口、消息超过观察终点、缺本地锚点及摘要/方向不一致。当前单份证据上限为 20000 会话、合计 200000 消息，超过即拒绝，在解析数组之前核对总量；大规模分段证据和原计划的更大恢复量仍待实现，不削减原验收范围。

`allDevicesStoppedAt` 在要求中指恢复之后独立重新核实全部设备停止的截止时间，不能直接沿用恢复前的旧停止声明。当前验证器只检查该可信时间与报告范围的关系，不自行取证设备物理状态。

输出绑定内容、完整签名封套和可信配置各自摘要，避免公钥或信任配置变更后沿用旧依据。纯验证器实例的配置是独立快照；现行管理员保存/查询每次读取维护要求和公钥撤销记录，撤销无需重启才能被识别。变更维护要求产生新编号，旧要求/回执保留，不提供普通管理员写信任配置的入口。

## 验证结果的含义

通过只表示“签名来源的声明经过认证、已知锚点及结构吻合”。签名本身不能发现来源隐瞒的备份后消息，也不能证明实机读取覆盖全部客户。专门回归模拟来源隐瞒一个本地未知的新消息，明确保持 `physicalHistoryVerifiedByThisCheck=false`。实机完整性必须由独立验收确认；辅助 0.4.0 的元数据/raw 诊断不具备该历史能力，不能据版本号注册为可信历史来源。

结果始终 `executionOutcomesVerified=false`、`canRelease=false`；不会修改账本、水位、未知发送、账号暂停或租约。已接通独立数据库管理员命令、不可变持久化和当前来源/完整依据重验，另有 [独立维护登记与公钥撤销命令](restore-history-maintenance.zh-CN.md)。HTTP 管理员工作台和最终恢复批准尚未接通。实际发送结果逐项核对、新运行边界、本地原子转换和中央精确准入仍待完成，不能将结构校验通过直接作为批准证书。

## 管理员保存与核对

先由可信维护人员使用 [维护登记命令](restore-history-maintenance.zh-CN.md)，在迁移 035、036 的维护表保存经过独立核验的实机来源、公钥及备份起点/所有设备停止依据，绑定当前完整清单和核对摘要；普通管理员和员工均无写入权限。命令和维护角色仅在隔离夹具使用合成来源验证，尚无经过真实平台验收的生产来源；不得照抄测试密钥或 true 能力值来运行生产。维护登记之后再收集绑定该要求和覆盖时间的来源签名报告。

准备私有 UTF-8 JSON 文件，结构为 `{ "requirementId": "维护要求UUID", "signedProof": { "proof": "合同定义的报告对象", "signature": "来源签名" } }`；proof 实际必须为完整对象。通过既有受保护环境配置 ADMIN_DATABASE_URL 和独立数据库管理员映射，在仓库根目录执行：

```powershell
node --import tsx server/scripts/admin.ts record-restore-history-proof --tenant <企业> --account <账号> --case <核对单UUID> --upload <上传UUID> --file <私有JSON路径>
node --import tsx server/scripts/admin.ts restore-history-proof --tenant <企业> --account <账号> --case <核对单UUID> --proof <原报告UUID>
```

文件和数据库中的报告均最多 1MiB，维护要求/回执最多 16KiB；合同的 200000 消息上限不是文件入口承诺，超过文件界限也拒绝，大规模分页仍待实现。保存文件不能包含任意公钥/来源配置、管理员标识或覆盖时间要求。响应丢失后按原文件/编号重试；不同内容不能沿用编号。原始正文/会话明细/公钥不进入返回回执，后台保留受 RLS 保护的摘要报告用于重验。

返回 `receipt` 是原不可变记录，`current.state` 单独表示当前可用性：`current`、`source_revoked`、`evidence_expired`、`requirement_superseded`、`basis_changed` 或 `state_unavailable`。current 只是当前核对元数据，不是运行许可；所有状态的 canRelease 都为 false。代码按公钥实际 DER 摘要查撤销记录，不因换版本/标签而恢复旧密钥，维护撤销和来源报告核验共享该公钥的事务锁。保存与审计同事务，失败不产生成功回执。具体结果见 [认证保存记录](superpowers/plans/2026-10-07-restore-history-records.md)。
