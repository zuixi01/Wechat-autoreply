# 知识管理

用户已确认需求：左侧新增知识管理，上传资料及表格作为共享知识库，结合回复模式和对象规则生成智能回复。实现保留现有自动发送准入，不通过知识上传绕过身份、中央审核和平台核验。

## 功能与验收

1. 资料管理：TXT / MD / CSV / JSON / DOCX / XLSX / 含文本 PDF；单份 10 MB，解析最长 30 秒，失败原因明确；可手动录入、编辑、分类、搜索、停用、删除及重新上传。
2. 本机持久化：用户数据目录 `knowledge/knowledge.sqlite` 保存文本、元数据、版本和 FTS5 索引；重启保留；处理中断标为失败。文件解析运行独立 worker，不阻塞桌面界面。
3. 检索：中文分词、二元字组和全文检索，最多 8 段；只用启用且解析成功的资料；修改、删除和停用更新库版本。无需向第三方发送全部文件或额外配置向量模型。
4. 试答：选择客户问题、回复模式与对象用户；使用主页的回复模型，展示回复及依据；无依据用可配置兜底；生成期间版本变化拒绝结果。试答不发送聊天消息。
5. 本地回复：现有 Provider 外接共享知识检索，基于提取文字检索，规则保留；版本变化取消旧回复；旧 Windows 引擎仍关闭。
6. 企业回复：企业服务使用已发布的受控知识。导出知识包，准备待审核发布文件，再由管理员按现有流程发布、评测、启用及同步。不能把本地文件直接伪装成已批准的业务记录；订单及金额动态事实仍需原受控记录。

## 企业发布

资料管理中的「企业知识发布」可导出 `autoreply-knowledge.json`。准备一个 JSON 文件，包含：

```json
{
  "publication": "替换为现有完整企业发布对象",
  "bundle": "替换为导出的完整知识包对象",
  "approvedBy": "管理员ID",
  "expiresAt": 1800000000000,
  "intents": { "资料UUID": "faq" },
  "replyRules": "使用礼貌、简洁的语气，资料未覆盖的信息先核实。"
}
```

intents 可用 faq、price、order、aftersales、other，每份资料需明确指定。运行：

```powershell
npm run knowledge:prepare -- --input 准备文件.json --output 待审核发布.json --tenant 企业ID --account 账号ID
```

工具创建新的知识及配置版本，最多 100 段，不覆盖已有输出文件。新发布保持 shadow / automaticEnabled=false，并取消旧评测批准引用；按现有管理员发布、评测准入及恢复流程启用。员工上传资料不能扩大设备权限。

本次服务端生成指令增加了回复规则约束，生成器指纹随之更新。发布前须按既有管理员流程读取当前生成器版本，确保基础发布对象中的 `textGeneratorVersion` 与实际服务一致，再评测和启用；旧指纹不能直接沿用。

- `npm run test:knowledge:desktop`：真实桌面 UI + 私有 IPC + 七种资料格式（含 PDF/DOCX/XLSX）解析与索引通过；手动录入、编辑版本、停用、删除、试答依据、无匹配兜底及旧问题结果隐藏通过。隔离的本机 HTTP 模型确认收到模式规则、统一开头、对象称呼和关系；没有向客户或外部模型发送测试内容。
- 150 万字左右的合成资料在后台索引；同时 73 次资料状态读取均可响应，最大延迟 10 ms。响应测试限制为单次 1500 ms，避免后台索引阻塞桌面控制。
- 页面截图检查：资料管理、规则试答、920 px 窄窗口布局；资料表格只在自身容器横向滚动。

最终复核修复：后台 worker 同时负责解析及索引（主线程不处理大资料分词）；企业检索参考最近 3 条客户文本（最多 8000 字）以支持连续追问；先按每份资料最多 3 段分散检索来源，再达到最多 8 段预算。三项均有回归覆盖。

边界：浏览器设计页使用离线演示资料和明确标注的演示回复；真实文件导入及模型请求应在桌面客户端测试。含扫描图片而无文本层的 PDF 需先转文字；企业自动回复须经过已有管理员知识发布、评测启用和平台核验。尚未用用户真实业务文件、真实供应商密钥及微信客户端完成自动发送实测。

决策：在当前已有大量未提交实现的工作目录中增量修改，不重建或替换工作树，以保留用户现有 UI 和运行环境。仅知识新文件、具名 IPC 与必要的接入点属于本轮范围。
