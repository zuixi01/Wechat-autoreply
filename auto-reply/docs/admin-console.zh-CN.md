# 企业管理员界面与独立管理服务

入口位于桌面客户端「企业连接」页面底部的「企业管理员」。沿用已有界面，新增管理员登录、设备状态、全员暂停、原批次查询及完整账号分页。此入口需要本次源码构建的客户端；已安装的旧版本不会自动获得这些功能。

## 部署管理服务

先执行中央迁移至 `033-tenant-pause-batches.sql`。正常员工服务继续使用 `DATABASE_URL`；管理服务是独立进程，使用已经映射到启用管理员的专用 PostgreSQL 登录。映射和权限设置见 [管理员部署说明](../server/admin/README.md)。不能使用超级用户、绕过 RLS 的登录或员工应用登录。

管理进程需要以下环境变量，保存在部署机器的私有配置中：

| 变量 | 用途 |
| --- | --- |
| `ADMIN_DATABASE_URL` | 专用管理员数据库连接，仅管理服务持有 |
| `ADMIN_TENANT_ID` | 本进程固定服务的企业 ID |
| `ADMIN_GATEWAY_TOKEN` | 独立的 43 位 base64url 管理凭据，不使用员工登记码或设备凭据 |
| `ADMIN_TLS_CERT_PATH` / `ADMIN_TLS_KEY_PATH` | HTTPS 证书及私钥，必须成对提供 |
| `ADMIN_BIND_HOST` | 默认 `127.0.0.1`；多电脑访问时配置监听地址 |
| `ADMIN_PORT` | 默认 `4783` |

在项目目录运行 `npm run admin:serve`。服务启动时核对数据库登录权限和管理员映射，每次操作再次核对管理员是否启用。正常服务不会自动开启管理端口。生产使用客户端可验证的 HTTPS 证书，不关闭证书校验。

仅本机开发可设置 `DEV_ALLOW_LOCAL_HTTP=1`，同时监听 `127.0.0.1` 或 `::1`；桌面客户端也须在开发模式运行，才接受本机 HTTP。此设置不开放远程明文访问。

凭据可在部署机器上用 Node 的 `randomBytes(32).toString('base64url')` 生成。不要把凭据放入 Git、截图、查询参数、聊天消息或员工配置。更换凭据需重启管理进程；旧凭据随后失效。

## 操作

1. 展开「企业管理员」，填写独立管理服务地址及管理员凭据，连接后界面显示服务端核对的企业和管理员。
2. 点击「刷新设备状态」，查看最近上报、过期上报、中央暂停与停止声明。超过一页时使用「下一页设备」，刷新返回首页。
3. 点击「暂停本企业全部账号」。界面生成并显示批次编号，主进程先提交本机记录，再发起暂停；记录无法保存时不提交请求。原账号及设备目标、子暂停请求和审计按 [企业全员暂停](bulk-pause.zh-CN.md) 的事务保存。
4. 查询本批次、逐页核对账号。后续状态替代了本批次暂停的账号仍会显示；后来新增账号计入独立计数。
5. 操作未确认时使用原编号查询或「重试原暂停批次」。同一编号不会重新暂停已恢复账号，也不会加入后来新增账号。已有批次确认后，「准备新暂停批次」可开始另一轮明确的暂停。
6. 完成后断开管理连接，清除主进程内存中的凭据。

凭据输入后立即清空输入框，仅保存在桌面主进程当前会话内，不写入配置或磁盘。客户端请求禁止重定向，并限制响应大小和最长等待时间；断开会取消请求并拒绝迟到登录结果。管理查询失败不返回数据库诊断或上游正文。

**暂停未确认不等于未执行。** 暂停编号及确认状态保存在本机用户数据目录的 `admin-operations/pause.sqlite`，使用 SQLite 完整提交及私有目录权限；只保存管理服务地址、实际企业/管理员标识、编号、时间和确认状态，不保存凭据、客户消息或数据库连接。切换页面、断开及重启后，同一服务和实际管理员重新认证时恢复原编号，不自动提交暂停；未确认编号不能被另一编号替换。服务器、企业或管理员变化时不会加载原记录。请另行保留未确认编号，不要删除数据库来绕过核对。

本机记录不可用时仍可连接并查看设备和历史批次，但新暂停必须先成功保存。服务端回复中的批次编号必须匹配请求；确认写入失败仍保留未确认状态。已确认的历史编号只查询服务端原记录，即使服务器恢复后原记录缺失，也不会因此重新创建暂停。查询不存在的编号不等于证实暂停没有执行，应结合服务端记录核对。

管理凭据绑定管理进程的固定企业和实际数据库登录，界面不能自行选企业或取得管理员身份。服务只开放身份查询、设备分页、全员暂停、批次摘要与账号分页五种操作；不开放 SQL、任意命令、恢复发送或登记码签发。浏览器直接带 Origin 请求会被拒绝，桌面通过经过来源核对的具体 IPC 调用主进程。

## 当前验证边界

嵌入式 PostgreSQL 的实际 SQL/HTTP 验证覆盖权限撤销、跨企业隔离、原批次幂等、输入界限和安全错误；实际 SQLite 重开覆盖丢响应后的原编号恢复和存储异常。独立桌面测试使用合成 IPC 数据，验证分页、失败重试、重新认证后恢复编号且不自动提交、存储失败提示和权限失效后清除页面数据。实际员工端使用的 HTTPS 证书、网络部署和多电脑联调仍需验收。

设备停止声明是程序上报，界面不会将其称为已验证的实际停止，也不会据此开放发送或解除恢复围栏。真实微信、企微后台收发能力、业务回复准确度和员工试点仍未完成。
