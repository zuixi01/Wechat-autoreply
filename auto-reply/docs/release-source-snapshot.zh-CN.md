# Windows 开发包的固定源码构建

`build:win:dev` 和 `build:win:installer:dev` 现在先生成独立的构建输入副本，再从该副本审计、发布辅助程序、类型检查、编译和打包。原工作区后续编辑不进入已经生成的副本；生成期间内容变化、路径别名或不完整输入会拒绝本次构建，保留失败目录。

## 输入与记录

构建副本位于 `.local/release-build/<UUID>/source`。只采集源码、脚本、原生项目、资源、构建素材、服务、测试、评测及明确列出的根配置/许可证文件；不复制 `.git`、`.local`、`node_modules`、原生 bin/obj、环境文件、密钥或 SQLite/DB 文件。副本和来源清单所在目录在写入前设置当前用户/SYSTEM 私有 ACL。

逐文件记录路径、字节数和 SHA-256，生成 `source-manifest.json`。先核对复制字节与原记录，再核对完整输入集合；编译打包结束后再次核对副本。新增、删除或改写副本文件均不能沿用原源码摘要。源码清单不进入应用归档，不复制员工设置、聊天数据库或运行权限。

成功的开发构建记录包含 `sourceSnapshotSha256`、`sourceSnapshotFiles` 和 `sourceSnapshotVerified=true`，同时绑定包锁和实际 ASAR 摘要。编译输出与辅助资源另存于同一 UUID 的 out/native 目录，现有包内和桌面检查可继续按该 UUID 运行。最新指针只在本次全部构建步骤通过后更新，失败不覆盖历史成功记录。

## 边界

副本通过受控目录连接复用本机 Node 依赖和 SDK，依赖物理文件与工具链仍共享，故 `dependenciesFrozen=false`。包锁摘要和新鲜 npm 生产/全部依赖审计继续保留；源码副本不能证明依赖、系统、环境变量或编译器是不可变的，也不是可重复构建或发布者签名证明。

当前命令仍生成未签名开发目录包，或在显式 installer 模式生成未签名安装候选文件；不执行安装、不自动启动业务回复。源码固定不代表完整回归、真实微信/企微后台收发、Jev 业务效果、普通账户干净安装/升级/卸载或多员工持续办公已通过。

实际执行和检查结果见 [本轮记录](superpowers/plans/2026-10-07-release-source-snapshot.md)。正式交付仍按原 D00–D20 验收要求完成。
