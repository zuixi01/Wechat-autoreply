# 员工设备凭据保护与开发检查

对应 D10/D15。员工主进程使用真实 Electron `safeStorage` 保护设备凭据，Windows 可用时才允许登记；中央模型密钥仍由服务器保管。

设备令牌、规范化的企业服务地址，以及企业、员工、账号、Agent 和平台范围现在共同放入 `autoreply-device-credential-v1` 加密正文。每次检查连接或认证请求，都在发送前核对密文中的地址和全部范围；改写外部登记记录不能改变令牌用途。标准 Base64、密文 64 KiB、解密正文 16 KiB 和严格字段约束均检查，错误只返回固定原因，不输出密文、令牌或系统异常原文。

## 升级旧设备

旧版本只加密裸令牌，不能证明其原始地址和范围，因此新版本拒绝这种密文，不根据可改写的旧记录自动补绑定。升级后需要管理员核对旧设备、未决操作及账号暂停状态，再按原登记流程提供新的有效登记码。员工在「企业连接」重新登记成功后，新记录才替换旧记录；失败不删除旧记录，也不自动重试已可能消费的登记码。自动回复仍须满足原平台、业务准入、租约和人工启动条件。

本变更不自动安装或升级当前员工电脑。正式安装、升级与回退仍按 [安装验收](windows-installer.zh-CN.md) 进行，不能用开发环境结果代替它们。

## 实际 Windows 检查

```powershell
& .\scripts\dev-tools.ps1 @('run','test:device-credentials')
```

此命令创建新的私有 `.local/reports/device-credential-check/<UUID>`，直接编译生产工厂和既有权限检查工具，再依次启动两个独立 Electron 进程。第一进程写密文、上下文和随机测试令牌的 SHA-256；第二进程重启读取、实际解密并比较摘要。没有明文令牌文件。真实 Windows 权限在写入前后核对，独立 profile 与净化环境隔离当前应用配置；不加载主应用、界面、聊天适配器或模型。

消费进程实际拒绝两种地址错绑、五项身份范围错绑、坏 Base64、损坏的 Windows 密文，以及真实 `safeStorage` 加密的旧裸令牌，共十项。版本、架构、实际进程编号和来源/编译摘要写入报告。每个子进程的总期限为 15 秒，既检查超时标志，也检查实际总耗时；结果写入新的文件，不覆盖失败历史。

当前有效报告为 `.local/reports/device-credential-check/a65932c4-cef4-4184-a964-b34fe1d33553/result.json`：五个子阶段全部退出 0 并确认关闭，真实加密与重启读取分别 730/707 ms，均在原期限内；Electron 44.5.1、Node 24.21.0、Windows x64。首轮 `3e31536e-feb5-4027-a23e-9efea75514a9` 的 producer 实际 21604 ms，原检查只看超时标志而错误记录 passed；保留为反证，不能作为 15 秒验收。已补启动后剩余时间和最终总耗时断言，首轮超过期限的具体原因尚未证明。

以上独立加密命令的证明限定为本机当前 Windows 用户、开发 Electron 与合成设备身份。另一操作系统用户、干净电脑、安装包、生产服务器注册、多人办公、原后台私聊和真实业务/费用仍须分别验收。

## 实际中央 HTTPS 整链路

Windows 上的完整 `server:release:check -- --release <候选目录>` 现在额外执行 `actual_windows_device_tls_connection`。在隔离 PostgreSQL 和候选包实际 HTTPS 服务中准备两个合成员工及一次性登记码，使用真实生产登记客户端、safeStorage 工厂和私有权限工具。三个独立开发 Electron 进程依次登记并保存密文、重启读取并续租，以及在中央撤销其中一台设备后验证认证拒绝和另一员工不受影响。证书验证保持启用，只加入显式公开测试 CA；没有加载聊天客户端、模型或主应用。

当前候选 `e9def321-84dc-404e-8d9e-9b576b3068df` 完整检查 55/55：实际 Electron 阶段 1929/1033/914 ms，所有九个子阶段在原 15 秒内。原 10 秒租约不变，重启与另一员工在撤销阶段保留原版本；实际 SQL 核对两台设备/两个租约/一个撤销/两个已用登记码，以及零模型尝试、发送许可和批准。登记码重用、租约冲突、跨账号及六项地址/范围错绑均验证。报告 `.local/reports/server-release/4bb1e76a-08aa-4f1d-8d7d-4f3edd76abbf/result.json` 与摘要审计 `.local/reports/windows-device-central-stage-ff9b8c7c-a5a0-43fa-b05d-bbae0f03145d.json` 保留实际进程、版本、来源与编译摘要。阶段进程关闭已观测；权限 worker 的全部后代关闭没有单独观测。

账号由隔离 operator SQL 准备，不能把本项当作新增管理员操作流程或实际安装后的中央登记证明。证明仍限定本机当前 OS 用户、开发 Electron、隔离服务和合成账号；真实生产服务器、安装/回退、另一用户、干净电脑与多电脑、原后台私聊和真实业务/费用继续待验收。完整 Jev 模拟评测与原发布检查保留，详见 [主线记录](mainline-development.zh-CN.md)。
