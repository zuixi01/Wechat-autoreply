# 独立中央服务部署候选

该目录由受信任的仓库构建生成，可独立复制到服务器。需要 Node 24.21.0 和 PostgreSQL 16；安装生产依赖使用 `npm ci --omit=dev --ignore-scripts`。运行不需要 Electron、桌面项目依赖、TypeScript 或 tsx。当前是部署候选，尚未完成生产部署、真实模型和员工客户端验收。

在仓库开发环境先执行 `npm ci --prefix server`、`npm run typecheck --prefix server` 和 `npm run build --prefix server`。构建输出新的 `.local/server-releases/<UUID>`，不会覆盖旧包。只复制输出目录，不直接复制开发中的 `server` 目录。构建包括锁定的生产依赖清单、编译后的共享模块、全部迁移、空配置模板和文件哈希清单；不读取或打包 `.env`、客户数据、测试数据、私有评测、证书或数据库凭据。

## 首次安装

1. 在新的目录放置完整候选包，核对 `release-manifest.json` 中的文件 SHA-256。此清单用于一致性核对，不代替签名或可信分发。
2. 使用独立迁移操作员按照完整文件名升序执行 `server/migrations/*.sql`，并按管理员操作规程建立登录及账号映射。应用启动不自动迁移。
3. 普通服务使用独立 LOGIN，仅授予 `autoreply_app`，不能有超级用户、BYPASSRLS、管理员或其他特权组成员资格。`ADMIN_DATABASE_URL`、`REVIEW_DATABASE_URL`、`LEARNING_DATABASE_URL` 分别属于独立管理员、业务评审和后台 worker，不能使用迁移操作员凭据。
4. 将 `.env.example` 作为变量名称参考，通过部署平台的私有环境配置注入数据库、TLS 和模型变量。应用不自动加载 `.env`。生产需要 HTTPS；`DEV_ALLOW_LOCAL_HTTP=1` 仅可配合回环地址用于开发验收。
5. 在发布目录执行 `npm run check`。退出 0 仅证明本地监听和完整生成配置通过检查；2 表示数据库或生成配置不完整；1 表示配置无效。它不连接数据库、不调用模型。
6. 执行 `npm start`。`GET /health` 只证明 HTTP 进程存活，不证明模型可用、数据库后续正常、平台收发或自动发送已授权。没有配置完整的模型变量时，回复生成保持不可用。

可用命令：`npm run admin -- --help`、`npm run admin:serve`、`npm run eval:jev -- --help`、`npm run memory:replay -- --help`、`npm run knowledge:prepare -- ...`。管理员和评审命令保持各自数据库身份约束；付费评测必须显式配置并单独执行。普通服务不承载管理员网关，管理员网关默认独立回环端口。

管理员 CLI 和网关使用实际独立 LOGIN，必须有效继承 `autoreply_admin`，不能同时拥有员工服务、学习 worker 或 Jev 审核角色，不能拥有或加入超级用户、BYPASSRLS、CREATEROLE、CREATEDB、REPLICATION 的角色。还需由迁移操作员在 `admin_database_principals` 绑定本企业的已启用管理员员工；仅授予角色不产生企业身份。网关只提供管理监控与暂停操作；开通员工账号和签发登记码使用独立管理员 CLI，登记码输出属于私有凭据，不能写入公共日志。新账号默认暂停，登记成功不授权自动回复；配置发布和启用仍须通过原独立业务评测与恢复门禁。

管理员网关使用 `ADMIN_TLS_CERT_PATH` 和 `ADMIN_TLS_KEY_PATH`，在建立数据库连接前检查 TLS；生产配置错误不会降级为 HTTP。停止时等待 HTTP 排空再关闭数据库，任一清理失败返回通用失败诊断；没有在普通员工服务中开放管理员数据库连接或任意命令接口。

编译模块保留原相对目录，因为学习评测会读取部署模块内容形成版本指纹。不要把它们重新合成单一脚本，不要局部替换共享模块；开发态 TS 和发布态 JS 的内容指纹可能不同，必须在同一发布版本中收集、复核评测证据。SQL 迁移也保留 `server/migrations` 路径；命令从发布目录运行。

## 运行与升级

由部署平台以普通系统用户管理进程，设置私有变量、HTTPS、日志权限和重启策略。不要把密钥放入命令行、版本清单或员工安装包。普通服务登录必须实际继承 `autoreply_app` 权限，只有成员资格但不能继承时也会拒绝；不能混用管理员、学习 worker、业务评审或特权身份。

数据库建立后，模型配置错误、初始化失败或端口占用均会进入统一清理并返回通用启动失败信息，不打印连接串或原始异常。后台 worker 只在监听成功后启动。SIGTERM/SIGINT 使用同一清理流程，先停止后台工作并等待 HTTP 排空，再尝试关闭所有数据库连接池；任一停止或关闭失败会报告失败，不能被视作已正常停止。Windows 服务管理器的停止方式仍需部署验收。

升级前暂停有关账号并确认各设备停止，备份数据库，在新目录安装依赖并核对包内容；迁移由独立操作员实施，再切换服务版本。不要用文件覆盖方式更新正在运行的服务。数据库迁移不保证可逆，不能直接回退 SQL；恢复和回滚按已核验的备份/维护流程实施。发布候选、健康接口和隔离测试结果均不解除自动回复准入门槛。
