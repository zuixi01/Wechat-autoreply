## 运行边界

使用独立迁移角色按顺序执行 `migrations/001-core.sql`、`002-reviewed-execution.sql`、`003-generation.sql`、`004-administration.sql`、`005-evaluation-admission.sql`、`006-human-confirmation.sql`、`007-reconciliation-cases.sql`、`008-device-reconciliation.sql`、`009-reconciliation-decisions.sql`、`010-execution-request-seals.sql`、`011-model-call-ledger.sql`、`012-generation-capacity.sql`。普通服务数据库登录角色须取得 `autoreply_app` 的权限，不能拥有 superuser/BYPASSRLS 或管理员角色；迁移凭据不用于普通服务。管理员使用独立非特权数据库登录及企业管理员映射，通过 [管理命令](admin/README.md) 完成员工账号创建、登记码、发布、评测冻结/准入/撤销、中央暂停、恢复、设备撤销、异常查询及核对开单/证据备注。自动发布必须绑定有效评测批准，旧布尔值不能单独授权；尚未开放管理 HTTP 或 GUI 入口。

开发运行仍可从仓库根目录执行 `npm run server:start`。独立服务器候选已增加自己的 package、lockfile 和 tsconfig：`npm ci --prefix server` 后执行 `npm run server:build`，输出新的 `.local/server-releases/<UUID>`。共享合同和核心模块编译到候选包的原相对目录，运行只需 Node 24.21.0 和锁定的生产依赖，不需要桌面 Electron 或 tsx。不要直接复制开发中的 `server` 目录。安装、权限、运行及升级步骤见 [独立部署说明](deployment.zh-CN.md)。

生产启动需 HTTPS 证书和 `.env.example` 中的私有配置。应用不会自动读取 `.env` 文件，请由启动环境注入变量。迁移部署须按完整文件名升序执行 `server/migrations` 的全部 SQL；目前至 `048-jev-blind-label-reviews.sql`，不能仅执行上面的历史 001–012 基线。发布包构建和隔离启动不能证明真实模型、客户私聊后台收发或生产就绪。

Jev 和文本模型密钥仅在服务端。文本客户端使用非流式 `/chat/completions`，要求提供者支持 JSON 输出，返回严格的 `{text,evidenceIds}`、结束原因 `stop` 以及匹配配置的实际模型 ID。兼容 API 的实际提供者须单独联调；没有声称所有兼容服务都可直接接入。

## 员工端 API

运行监控与目的绑定暂停需要先由独立迁移角色补齐按序执行的迁移至 `032-account-pause-confirmation.sql`。`POST /v1/runtime/status` 保存登记设备运行元数据；暂停挑战及确认限定设备、用途、请求和进程轮次，不授予执行权。管理员使用 `runtime-status`、`request-pause` 和 `pause-request`。操作见 [运行监控](../docs/runtime-monitoring.zh-CN.md)及 [账号暂停与停止确认](../docs/account-pause.zh-CN.md)。

企业全员暂停补齐迁移至 `033-tenant-pause-batches.sql`，管理员使用 `request-pause-all`、`pause-all-request`、`pause-all-accounts`。一次事务覆盖原全部账号，保留固定目标清单并支持完整分页，失败不会留下部分暂停。边界及重试规则见 [全员暂停](../docs/bulk-pause.zh-CN.md)。

所有员工接口均使用登记后设备 Bearer 凭据；企业、员工、账号、平台和设备由该凭据导出。员工端不能上传替代策略、知识或模型配置。

核对恢复还提供 `POST /v1/reconciliation/decision`（读取管理员决定或 null）与 `POST /v1/reconciliation/applied`（补交已持久化的精确决定应用确认），用途与约束见下文。两者不签发发送许可，不主动启动设备。另有私有 `POST /v1/reconciliation/seal` / `seal-applied`，用于响应丢失且原日志确证尚未发送的请求永久封存及应用确认，详见 [管理操作](admin/README.md#许可申请响应丢失先永久封存原请求)。中央封存和本地持久化两项缺一均不得清除阻断；已有许可只读返回，永不重发。

健康接口 `GET /health` 只表示服务进程存活，没有数据库、模型或收发就绪保证。浏览器 Origin 默认拒绝；员工主进程使用固定服务地址，拒绝重定向，凭据不暴露给渲染进程。

`POST /v1/replies/review-edited` 接受严格的 `{generation,edit}`；`generation` 与生成接口使用同一任务/上下文合同，`edit` 为最终文本、新 `draftRevision`（至少 2）及去重后的原知识引用 ID。原文字节（包括首尾空白）参与哈希，不复用旧审核，不调用文本生成器。服务端重跑前置判断及五项审核，仍从已发布知识中筛选当前企业、账号、客户及有效期内的依据。编辑任务和自动生成任务的请求哈希区分用途；同任务重复请求只返回仍有效的原结果，改动文本或用途冲突时拒绝，不重放未完成请求。

该接口只返回审核数据，`automaticAllowed` 恒为 `false`，不写入 `reviewed_replies`，不能凭返回结果取得自动执行许可。缺知识或客户明确要求人工时，服务端仍可保存员工精确改写的草稿，并返回实际人工处理原因；这不是事实或 Jev 审核通过。具名工作台接口在已接管、物理停止确认的会话中允许员工编辑重审，或核对当前显示的客户和草稿后点击“我已核对，确认发送”。

人工确认的渲染进程请求只包含任务 ID 和预期版本。主进程从持久化记录及当前可信会话构造新的任务和至多 5 秒的确认；服务端校验设备身份、当前发布、租约、已完成源任务及精确文本/哈希/版本/引用，原子保存不可变 `human_confirmations`、人工目的许可和审计。许可明确标记 `purpose=human` 及确认 ID，不伪造自动审核批准。确认来自受信任桌面主进程和已认证设备，不是独立证明物理人类点击的加密证据。

人工操作与自动回复使用同一个 Sender、中央 outbox、物理执行器和账本。关闭自动回复或处于影子模式可以人工确认；全局暂停、账号暂停、租约失效、输入或草稿冲突、新消息/客户变化、能力未经验证和未知执行仍会阻断。许可到手后再次核验；结果未知、许可响应不明及重启均不能自动重发。发送后继续保留人工接管。真实平台适配尚未安装，当前链路只在合成设备上验证，不表示真实微信/企微已可发送。

## 企业候选验证与 auto 调度

迁移至 `018-learning-validation-runs.sql` 后，同一专用学习连接可启动 validator。除复盘配置外，需要完整的 `TYPESAFE_API_KEY` 和 `TEXT_MODEL_API_KEY`、`TEXT_MODEL_BASE_URL`、`TEXT_MODEL_ID`、`TEXT_MODEL_EXPECTED_ID`。这些是主机配置；校准案例不能覆盖模型、端点或密钥。validator 与 reviewer 使用相同的非特权角色检查、有效账号绑定、账号后台租约和 UTC 日学习 token 账本。

启动/重启会从权威数据库发现 auto 模式的自动候选，排除固定方法、个人偏好、归档项和已生效修订。没有至少五个独立人工校准会话或存在训练重叠时，不调用模型。实际校准使用已发布知识、回复规则、检索策略以及文本生成器指纹，分别回放现行和候选方法；两组保持其他方法一致，人工期望/评分用语不进入供应商请求。每个校准案例最多涉及两组各三次 HTTP（Jev 前置、文本生成、Jev 审核），另有一次方法语义风险核验；每次请求单独先占额，再结算实际或保守用量。

验证不会创建真实生成任务、审核记录或发送许可。合格凭据有效期 24 小时，绑定实际来源、方法、知识、策略、模型验证器和人工数据集。suggest 只保存结果；切换到 auto 可消费仍有效的凭据，避免重复调用模型。明确的方法/覆盖/风险拒绝不会在相同验证依据下反复扣费，模型故障使用持久退避和尝试上限。前台活动、暂停、关闭学习、撤销、遗忘、依据变化和停机阻断提交；迟到复盘响应只能结算费用，无法激活方法。原始文本/Jev HTTP 在取消后没有可验证用量时保留上界，不冒充免费请求。

方法在存储中激活后，原有企业发布及评估准入仍须重新完成，旧发布不能继续生成。validator 不授予发布或发送权限。管理路由、维护与模型合并已接通；真实工作台操作入口和学习专用 Electron 验收仍在开发。合成 HTTP 和数据库测试不能证明真实业务效果。

## 生成与执行

上下文最多 40 条、合计 32000 字符，连续账本序号；待回复入站最多 30 条、单条 8000 字符、合计 24000 字符。每个请求绑定完整身份、客户、原消息区间、上下文哈希及配置/知识/策略/问题集版本。历史出站消息可作为上下文，但不作为本轮待回复问题。

模型请求在数据库事务之外执行。生成完成后再次锁定账号并核对当前租约、设备、暂停状态和发布版本；过期或撤销的结果不能成为可发送候选。当前自动事实校验仅放行经过审核的有效知识原文组合，其他措辞转人工。

生成和编辑重审结果现在可包含 `explanation`，用于员工核对：绑定源任务、上下文、知识版本及最终草稿哈希/版本，保存识别到的全部意图、生成时处理建议和事实检查状态。服务端从实际草稿引用中选择当前企业/账号/客户作用域、知识版本、意图及有效期均匹配的资料；只展示最多 8 条，每条摘录最多 600 字符，不展示未引用或不适用的知识。未展示、不可用引用分别计数，界面不会把缺失依据当成事实通过。人工发送继承原评估的源任务 ID，编辑重审重新生成说明，旧缓存没有说明时显示缺失提示。

这些说明是历史评估数据，不是发送许可或 Jev 的长篇推理。界面由程序原因码生成意图不明、范围、事实、诉求覆盖、表达、指令干扰及取消等可读提示；资料有效期改变会提示重新核实。回复结果及引用原文端点接收至多 256 KiB 的响应，按实际流字节复核，不信任 Content-Length；其他认证、租约和许可结果保持 64 KiB 上限。

`POST /v1/replies/evidence` 为认证后的只读引用入口。严格输入为 `{taskId,contextHash,knowledgeVersion,draftHash,draftRevision,offset}`，不能指定企业、客户、知识条目或任意资料地址。服务端在账号权限锁内查询当前登记 Agent 的已完成源任务，核对任务和最终草稿，从该任务的不可变发布版本读取知识；只返回实际引用、适用于原企业/账号/客户及已识别意图、在原评估时有效的条目。每页一条完整的已发布知识正文（最多 20000 字符），提供可查看总数、不可用引用数和下一页位置。原评估时间随新结果保存；旧记录回退到审核时间或任务创建时间，不能由员工请求改写。

资料核对不要求账号运行或租约有效，但仍要求员工账号启用、归属和设备凭据有效；撤销设备后不能继续读取。后续发布不会把历史引用替换为新版本，当前已过期时界面提示重新核实。主进程从本地记录构造请求，人工发送记录继续关联原评估；最多并发 2 次、每次 5 秒，返回后重新检查登记作用域和记录版本。具名 IPC 仅接受任务 ID、预期版本和分页位置，原文不持久化到本地工作台，也不随每两秒轮询重复拉取。界面每次保留一条原文，支持前后翻页、键盘滚动和重读；任务变化清除已打开资料。查看不会调用模型、申请许可、解除人工接管或改变发送状态。这一入口只展示知识库保存的引用条目全文，不抓取来源标注指向的外部文件。

已实现员工主进程私有租约、生成、许可及结算传输，`LeaseSession` 管理单调时钟到期、周期续期、取消和迟到结果，已由 `DesktopAgentRuntime` 接入 Electron 生命周期。`CentralSendAdapter` 使用同一 SQLite 账本持久化许可与回执，先写意图再申请、先写动作标记再调用设备，确认回执与原入站处理水位同事务保存。补交回执不会调用设备或申请许可。

重启发现已存许可但尚未调用设备时，记录未发送回执；动作标记后缺回执则保持未知。许可请求响应丢失保留待管理员对账记录，不自动重新申请。待结算或需要对账均暂停账号自动处理；正常补交按当前设备作用域筛选，包括旧登录轮次。管理员现可查询已签发及未知许可元数据，并为已有许可开核对单、追加证据备注。开单和中央暂停/审计同事务；原任务、草稿、身份、租约与结算哈希冻结为不可变快照。备注只保存内部证据编号、SHA-256 和实际观察时间，最多 100 条；重复 ID 和相同内容幂等，不同内容被拒绝。核对单及备注不能修改/删除；普通服务只读核对快照、不能访问管理员备注，管理员也不能修改许可结果。中央暂停不等于设备停止，证据备注不等于可信物理证明；管理员结案、设备应用确认及本地原子恢复协议已实现；真实平台取证和生产故障演练仍待验收。未知回执不能由员工自行变成确认。实际平台未安装，自动发送保持关闭。禁止把 HTTP 许可申请、测试替身回执当成真实设备发送证据。

`POST /v1/reconciliation/decision` 和 `POST /v1/reconciliation/applied` 使用原核对单、快照/报告哈希及原许可请求，不接受客户端指定其他账号。读取返回独立决定或 null，应用确认精确绑定决定 ID 和内容哈希；两个入口均为私有凭据、严格合同、8 KiB 上限。应用确认与审计同一事务，仅确认的决定可解除原许可的准入阻断，许可状态及原结算哈希保持历史值。管理员仍不能直接更新许可或结案表，结案只能调用迁移 009 的限定函数。

## 企业学习复盘 worker

迁移至 `016-learning-worker.sql` 后，服务启动可接入持久复盘队列。`LEARNING_DATABASE_URL` 必须使用独立登录，该登录属于 `autoreply_learning_worker`，且不能是超级用户、绕过 RLS、创建角色、复制或管理员角色。普通 `DATABASE_URL` 仍供生成/执行服务使用；两个连接的权限分别检查。后台登录只通过显式 `learning_worker_bindings` 取得指定账号的授权，不保存明文设备凭据。绑定的设备被撤销或轮换凭据后，旧绑定失效；重新授权需要管理员另行操作。

模型由服务端环境配置：`LEARNING_REVIEW_API_KEY`、`LEARNING_REVIEW_BASE_URL`、`LEARNING_REVIEW_MODEL_ID`，缺省分别继承 `TEXT_MODEL_API_KEY`、`TEXT_MODEL_BASE_URL`、`TEXT_MODEL_ID`。`LEARNING_REVIEW_CONFIGURATION_ID` 为设置中可选的配置 ID，缺省为复盘模型 ID。客户文本不能指定端点或密钥；未知配置 ID 不会回退到其他模型。缺少后台连接或模型配置时，启动日志明确说明复盘未启用，不认领任务、不占模型费用。指定了后台连接但使用不合格角色时，服务启动失败。

初次部署须用受信任的迁移/管理员通道创建独立登录并绑定账号。例如下面操作只建立显式授权，不调用模型或发布记忆；登录密码按部署的数据库凭据管理方式配置：

```sql
CREATE ROLE enterprise_learning LOGIN NOSUPERUSER NOBYPASSRLS NOCREATEROLE NOCREATEDB;
GRANT autoreply_learning_worker TO enterprise_learning;
-- 将下面三个 ID 替换为经过管理员核验的企业、账号和设备。
INSERT INTO autoreply.learning_worker_bindings
  (id,login_name,tenant_id,account_id,employee_id,agent_id,agent_token_hash)
SELECT gen_random_uuid(),'enterprise_learning',tenant_id,account_id,employee_id,id,token_hash
FROM autoreply.agents
WHERE tenant_id='verified-tenant' AND account_id='verified-account'
  AND id='verified-agent' AND revoked_at IS NULL;
```

worker 在每次启动时重新枚举有效授权，从 PostgreSQL 认领任务。认领、最坏费用预占和候选提交使用账号事务锁，模型 HTTP 期间不持有事务；两个 runtime 竞争同一任务只产生一次认领。候选与任务完成原子保存，候选保持待审，不直接激活或发布。前台活动、关闭学习、暂停、遗忘、来源失效或上下文变化会阻止提交并取消进行中的复盘。超时/停止不能证明供应商未收费，因此保留预占；迟到用量仅结算原请求，不能恢复候选或已遗忘的范围。关闭服务会先停止复盘，再关闭数据库连接。

此处已接入复盘、成对回放验证、维护与可选模型合并 runtime，以及经过设备认证的学习管理 HTTP 入口和人工触发的双重身份桥接。管理界面、实际工作台纠正与问题聚合事件仍在开发。合成 loopback HTTP 和独立 PostgreSQL 测试验证工程行为，不代表真实业务学习效果。

验证采用短租约：单次请求超时加 5 秒，仅在下一次调用通过预算准入后续租。大校准集的进程退出不会占住账号数小时。后台状态扫描默认 500 毫秒，每次请求和提交也检查当前权限与验证依据。

## 企业学习维护

迁移 `021-learning-maintenance.sql` 保存每个账号/客户范围的首次观察、周整理和小时保留期清理时间，以及最近 100 份整理报告。服务配置专用 `LEARNING_DATABASE_URL` 后启动维护 worker；未配置模型时仍可维护数据。默认每分钟扫描绑定，首次只初始化；7 天间隔且前台空闲 2 小时后，根据真实加载/采纳记录、更新时间和当前修订年龄决定维护。新自动方法宽限 14 天，闲置 14 天标为待复核，30 天可恢复归档；人工来源和固定项保持原状。待复核/归档不会被计为使用，也不会重置闲置时间。

每小时按有效 `caseRetentionDays` 清理实际案例与人工校准正文。关闭学习不会关闭保留期策略；账号暂停、前台活动和有效复盘/验证租约会延后本轮维护。确定性维护不调用模型，不产生模型费用；它在共用账号锁中完成，与其他后台认领互斥，过期租约可以回收。方法变化、审计、整理报告和调度时间原子提交；停机到达事务最后一次异步写入时也检查取消并回滚。范围遗忘删除维护状态和报告。

迁移 `024-learning-episode-closures.sql` 为真实生成片段保存空闲关闭出处。维护每轮在相同授权账号事务中检查 30 分钟期限，不受小时清理节流影响；只有已登记生成、没有明确纠正/结果的片段才关闭为 unknown。没有可信问题关联时，同一客户的不同片段保持独立，不按昵称或模型猜测合并。关闭派生案例保持原证据保留期，原始草稿不修改；超时不代表解决、采纳或失败，不排模型复盘、不计新方法使用。后续明确反馈仍可提交，生成检索优先使用明确反馈，旧关闭记录仍可查；遗忘和到期通过外键清除关闭出处。普通应用角色不能写入超时关闭出处。前台未空闲、账号暂停、有效后台租约和停机取消均阻止本轮提交。

迁移 `022-learning-curation-merges.sql` 后，可选模型合并复用主机复盘模型配置、账号后台租约与费用预算；`curatorMergeEnabled` 默认关闭，缺模型时返回 `curation_merge_unconfigured`。合并保留完整来源和不可变替代清单，先创建候选，旧方法继续生效。候选被人工修订后仍继承替代约束；旧方法被固定、编辑或遗忘后，旧合并不能生效。验证比较整个旧方法组与新方法，候选组不能借用旧方法。新方法生效、旧方法归档、凭据消费和审计同事务完成，不自动发布。已发生费用在遗忘后只保留匿名占额，不为迟到响应恢复客户数据。

## 企业学习管理接口

生产应用注册 `POST /v1/learning/{operation}`，使用现有设备 Bearer 认证；服务端推导企业和账号，正文只能选择 `conversationId`（省略或 null 表示账号方法）。客户端自报 tenant/account/scope、后台引用、方法 source 或验证通过凭据均被拒绝。请求正文最大 2 MiB，范围快照与组合写入共用一个已授权账号事务。

已接通操作：`snapshot`、`detail`、`settings`、`action`、`manual`、`review`、`cancel`、`forget-scope`、`calibration`、`reports`、`search`。`action` 的 `command` 复用桌面版本动作合同并去掉 scope，由主机绑定实际身份。人工教导 `manual` 必须带稳定 `sourceId`，案例、候选和审计原子保存；相同内容重试不新建，来源内容变化返回冲突。`review` 持久排队，后台仍受学习开关和预算约束。

迁移 `023-learning-events.sql` 后，实际生成完成同时保存草稿案例和实际加载的方法修订。生成完成、自动审核记录和学习来源在同一账号事务中提交；案例保存失败不能留下可用审核。初始案例结果为 unknown，不自动排入成功复盘；尚未关闭的实际草稿不进入历史案例检索。

新增 `correction`、`result`、`feedback` 操作。正文必须带 `reference: {taskId,contextHash,draftHash,draftRevision}` 和稳定 `sourceId`，并分别组合共享纠正、结果或人工反馈合同。服务端读取已保存的完整生产任务与草稿，推导客户及实际加载方法；正文不能指定 scope、conversationId、problemId 或 memoryRefs。旧发送有效期和暂停不妨碍授权员工提交保留期内的历史反馈；设备撤销、伪造草稿、来源过期或遗忘仍拒绝。

纠正与明确结果产生不可变的派生案例，继承原案例的保留基准，不能通过迟到反馈延长旧正文的寿命。确认解决时保留最近一次员工纠正；同毫秒事件按持久序号判断先后。案例、反馈、复盘队列和员工事件审计同事务保存，重复 ID/相同内容重试只保存一次，内容变化返回冲突。明确采纳单独计量；发送和生成不计为采纳或解决。事实错误/不当承诺隔离实际加载的修订并触发严重错误复盘；两次不同的重复追问反馈触发质量失败复盘。

校准导入的作者来自认证员工身份；接口不能签发激活凭据。搜索仅返回当前授权范围内尚未过期的案例，最多 20 条；遗忘后不能重建同来源。报告按时间展示最近 100 条。`validate` 和 `curate` 通过主机持有的专用后台连接执行，正文不能选择 worker 引用。每次占额、读取与提交同时检查当前调用设备与 worker 绑定；同账号的其他有效设备可以调用，调用设备撤销/凭据轮换后不能借用仍有效的 worker 授权。断连和停机取消进行中的人工学习操作，并在关闭数据库前等待它们结束。没有专用连接时返回 503 未配置；没有验证模型配置时验证也返回未配置，确定性维护仍可运行。实际工作台反馈、企业客户端与桌面完整流程仍待后续验收。

## 存储与容量（执行记录）

核对协议由迁移 008 和独立 `ReconciliationAuthority` 提供。挑战读取原不可变快照，仅返回当前设备自身已有许可且 `newlyIssued=false`；不会自动开单、申请新许可或恢复执行。报告绑定原企业/员工/账号/Agent/平台、登录轮次、客户、任务/草稿哈希及版本、租约、用途和核对快照。观察时间不早于开单及许可到期，不能晚于数据库当前时间；报告与审计原子保存。服务可以读取核对快照、追加设备报告，管理员只能读取设备报告，双方均没有修改/删除设备报告的权限；管理员证据备注不向普通服务开放。设备断言属于受信任 Agent/执行器边界，不能单靠 HTTP 合同独立证明实际物理停止。

主进程具名 `agent-workbench:reconcile` 只接收任务 ID 和记录版本，暂停实际观察、续租、Sender 和结算工作后取证。没有停止确认、原生 `inspectExecution`、可信非触发日志或已核验新回显时保持未知，不把超时、消息不可见或旧回显当成证据。SQLite v9 先保存报告，再提交 HTTP；断网重试补交同一份报告，重启仍保留原回执、消息水位和未知阻断。人工接管不自动释放，取证期间不能启动自动运行或并发取证。工作台现已接入核对按钮；未安装可信取证器且无缓存报告时不可操作。管理员追加不可变结案决定后，本地原子应用发送状态、原入站区间处理水位和人工接管，随后补交应用确认；确认前中央及本地均不解除阻断。原回执不覆盖，两种结案都不重发原消息。自动回复继续暂停，管理员恢复与员工启动分别显式执行。真实平台取证和生产恢复仍未验收。

发布保存完整配置、策略和业务知识；生成任务保存请求哈希、任务元数据、最终候选及用于核对的有限资料摘录，不保存完整入站上下文。人工确认记录保存确认、任务元数据和请求哈希，最终文本从源任务绑定，不额外复制到确认表。最终回复、客户专属资料摘录仍可能含客户信息，生产前需完成保存期限、数据库/备份加密和删除流程。逐次调用的验证答案、阶段耗时和可观察用量已记录；货币费用与账单核对仍待实现。

迁移 012 为同一个中央数据库的所有服务实例设置逻辑生成准入：总计 10 个有效任务、每账号 2 个，超出返回 429。生成与员工编辑重审共用这一限制，单进程仍有本地资源上限。命中已完成任务缓存时不会再次调用模型，但真实提供者费用预算及故障恢复流程仍需开发。

自动测试使用 PGlite 执行实际迁移和 SQL，并通过本地 HTTP 连接员工客户端；Jev、文本模型和设备均为合成替身。PGlite 只有单连接；独立 test:postgres 已验证指定的真实多连接额度/租约/封存争锁和数据库故障。完整跨进程部署、容量、真实设备和业务评测仍须验收。

## 逐次模型调用与账号额度

生产启动将 Jev 和文本 HTTP 请求接入数据库账本。迁移 001–012 后，管理员必须为每个账号配置每日请求次数额度；未配置或额度用完，生成返回 `handoff` 及明确原因，不调用供应商，不产生自动候选。已有完成任务的缓存复用不占新额度。额度及逐次记录查询见 [管理操作](admin/README.md#模型调用记录和每日请求额度)。

账本记录前置/文本/后置、实际重试、输入/问题哈希、固定版本、请求/实际模型、经过验证的 Jev 答案、已知 token、耗时及失败类别。中央普通应用日志不输出供应商错误正文、客户状态或密钥。原响应即使在账号暂停/设备撤销后返回也能记录，不重新授权；存储故障使本次评估不能通过。该记录器在生产入口强制安装，独立合成管线测试仍可不安装 HTTP 记录器。

请求额度按数据库 UTC 日和同一账号锁共享；保留失败及未知预占。费用未知不计为零。当前额度不能证明费用硬限制或全局并发限制；价格/币种/账单与货币预算仍待实现；真实多连接的指定额度场景已经独立验证，生产部署仍须验收。

真实 SQL 并发回归使用 `npm run test:postgres`，自动建立并清理独立的 loopback PostgreSQL 测试容器；详见 [环境与专项说明](../docs/development-environment.md#真实-postgresql-多连接专项)。报告包含镜像 digest、PostgreSQL 版本和非特权实际登录。不得将测试 URL 指向现有企业数据库。日常 `npm test` 保持单连接合成回归，专项当前另计 20 项；不会调用真实模型或聊天客户端。

## 跨实例生成准入

迁移 012 的触发器在写入 running 任务时，使用固定名称的数据库事务 advisory 锁，读取提交后的全租户有效任务数；达到总计 10 或本账号 2 即拒绝准入。锁只覆盖数据库事务，不能跨模型 HTTP 持有。任务完成/失败或达到数据库截止时间后释放逻辑名额；过期行保留，不重放、延长或重新启动原任务。完成任务缓存不新增名额；绑定和截止时间不可修改，过期 running 行不能完成，也不能发起新的模型阶段。参考 [PostgreSQL 事务锁](https://www.postgresql.org/docs/16/explicit-locking.html#ADVISORY-LOCKS)。

生产 Postgres.transaction 显式使用 READ COMMITTED；触发器拒绝直接用其他隔离级别准入/占模型额度，避免计数来自等待前的旧快照。特权计数器固定 search_path、无公共/应用/管理员直接执行权限，保持由独立 BYPASSRLS 凭据角色拥有；设置 row_security=off 使错误的普通角色拥有者导致拒绝，而非少计其他企业。该设置自身不会绕过 RLS，见 [PostgreSQL RLS 说明](https://www.postgresql.org/docs/16/ddl-rowsecurity.html)。

这约束本系统有效生成任务，不承诺超时/取消后的远程供应商已经停止或不会收费。每日请求预占仍保留；账单未知不退款。不扩张发送权限、不自动恢复账号，且不等于跨数据库集群或实际三服务器部署验收。生产升级先停止新生成、等待旧任务排空/截止，再依次迁移至 012，并同步升级所有服务；已有超限任务不会被迁移自动取消。

### 工作记忆窗口的实际任务反馈

`POST /v1/learning/episode-correction`、`/episode-result`、`/episode-feedback` 使用当前设备认证和严格的 conversationId/episodeId/来源事件输入。服务端把原始或派生案例追溯到已保存的完成任务，并重新校验实际草稿、当前员工/账号、保留期及来源幂等；客户端不能提交任务身份或方法引用。相同账号的另一授权设备可提交；人工教导案例不能冒充生产生成。现有 `/correction`、`/result`、`/feedback` 的实际 task reference 合同保留。这些操作不签发发送许可，也不代替企业正式发布。
