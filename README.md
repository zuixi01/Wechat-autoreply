# 微信自动回复

Windows 个人微信自动回复客户端，包含独立的企业回复服务。基于 SightFlow 开发，采用 Electron、React、视觉模型与本项目的 Windows 窗口辅助程序。许可证为 Apache-2.0，原项目归属与第三方说明见 NOTICE 和 LICENSE。

个人微信是默认入口：选择联系人 → 读取完整文字消息 → 按回复规则与知识库生成 → 核对联系人、窗口和草稿 → 保存发送记录 → 发送 → 核对微信中的回复回显。整个流程通过前台截图运行，需要微信保持在前台；切换应用或通知遮挡聊天时等待，恢复可见后重新校验。

## 启动

开发环境需要 Windows x64、Node.js 24.21 或兼容的 Node 24，以及 .NET 10 SDK。当前工作区已配置的工具链位于 `.local/toolchain`；新克隆可使用系统安装的工具链。原生输入依赖安装失败时需安装 Windows C++ 构建工具。

```powershell
npm ci
npm run dev
```

开发启动和普通构建会自动准备个人微信窗口辅助程序，并在构建时校验其哈希。企业发布包另行包含企业适配器。

已打包的本地工作区可双击根目录 `启动微信自动回复.cmd`，自动打开最近一次成功构建的版本。

1. 登录个人微信，关闭多开窗口，把完整窗口放在主显示器内。
2. 在“模型配置”中添加兼容 Chat Completions 的 HTTPS 模型接口和密钥，测试连接。视觉模型必须支持图片输入；主页分别选择视觉模型和回复模型。
3. 在主页保存统一回复规则。可在“对象用户”中配置准确备注名对应的专属要求，也可导入知识资料。
4. 输入联系人的准确备注名，点击“启动个人微信自动回复”。同名或搜索不完整时，先在微信打开指定单聊并清空草稿，再点击“接入已打开的聊天”。
5. 首次启动忽略历史消息，只处理之后收到的完整文字消息。暂停及程序重启会保留处理进度，重新启动后核对并继续。更换窗口、修改规则或人工接管后，可选择“以当前消息重新接入”。

发现人工草稿或人工回复时等待本人操作完成，再核对并继续；消息断层或无法确认对象时停止输入。已经按下发送键但暂时读不清回显时，会保留记录并持续复核，只读取、不重新输入或发送。退出程序后仍未核对的记录会阻止重新启动；在微信人工核对后，勾选确认并标记已发送或未发送，再重新启动。这条消息不会自动重发。

短暂网络故障、接口繁忙或识别失败会持续等待恢复，包括首次连接时；等待时间逐步增加到最多 30 秒，界面重试计数最多显示六次。消息衔接异常只重新识别两次。期间保留未处理消息，重试不重复发送。界面显示恢复状态、上次回复耗时和最近模型耗时。画面完全相同且窗口与配置一致时复用识别结果，最多 30 秒；支持的文字气泡按实际像素分割，相同文字在不同位置仍保留为独立消息，只向模型提交尚未识别的气泡。仅输入区域变化时保留像素一致的已核对历史，单独读取草稿。联系人标题、窗口或配置变化后重新核验完整画面；消息连续性识别失败时重新读取整图，纠正错误的气泡缓存。点击输入框引起画面变化时，在输入前重新核对聊天并保存新锚点；发送前两次原生读回全文，发送后原生核对空输入框并检查新增回复气泡。不重复输入或按下发送键。

同一个微信进程在两次读取之间移动或调整大小会重新核对画面，发送途中位置变化仍会停止。旧版本保存的窗口身份格式不同，升级后若提示窗口变化，请人工核对微信，再勾选“以当前消息重新接入”一次；已有发送记录会保留。

“多联系人批量自动回复”作为展开功能保留，仅处理填写名单中的联系人。未读数字和经过像素核对的小红点可触发自动切换聊天；打开聊天前保存任务，重启后恢复每位联系人的处理基线。单联系人与批量模式共享进度，发送结果暂不明确时只复核当前回复，不重复发送。使用与验收边界见 [批量模式说明](docs/personal-wechat-batch.zh-CN.md)。

## 企业能力

企业连接、服务端、数据库迁移、工作记忆和人工审核功能保留。客户端首次进入企业功能或工作记忆时才初始化相关服务。企业服务安装与发布见 [server/README.md](server/README.md)，能力边界见 [企业微信能力报告](docs/capability-report.wework.md)。企业后台真实收发需要经过验证的平台适配器，当前窗口探测辅助程序本身不提供后台聊天收发能力。

## 验证和打包

```powershell
npm run test:personal                 # 隔离完整流程：模拟桌面、实际本地 HTTP、实际 SQLite
npm run test:foreground-input         # Windows 焦点结构与 Unicode 字符验证，不操作桌面
npm run verify                        # 类型检查、静态检查、全部单元/集成/回归测试
npm run build                         # 开发构建
npm run build:win:dev                  # 隔离的 Windows 可运行版本
npm run test:desktop:release           # 实际 Electron 界面与 IPC 验证，独立测试资料
npm run build:win:installer:dev        # Windows 安装包
```

只有明确授权的测试联系人才能进行真实发送验收：

```powershell
npm run test:wechat -- --target "准确备注名"
# 已手动选定聊天时添加 --current-chat
# 连续验收三轮，每次收到回复后再发下一条：
npm run test:wechat -- --target "准确备注名" --current-chat --replies 3 --timeout 600000
```

实机脚本使用实际应用资料和模型接口，等待该联系人发送新消息；默认核对一条回复，`--replies` 可指定连续 1–10 轮，全部确认回显后才暂停退出。普通客户端持续监听，次数限制仅用于验收脚本。不能收到新消息或验证失败会报告失败，不会用历史消息代替验收。报告位于 `.local/reports/personal-wechat`，记录状态变化、模型请求和回复耗时，不上传聊天内容和密钥。

中文搜索和回复通过完整 Unicode 文本粘贴，包含 emoji。辅助程序先保存剪贴板各格式的数据，在每次操作前后核对窗口、进程和焦点；复制编辑框全文进行精确读回，再恢复原剪贴板。图片按完整 DIB 数据恢复，辅助进程退出后仍可读取；如果用户期间复制了新内容，不覆盖新内容。不支持安全保存的格式会在输入前停止。

已识别文字会随气泡像素指纹保存到本地接入记录，重连时先复用对应文字，再校验当前聊天。历史比对允许识别中的全角/半角标点和标点周围空白差异；发送草稿必须与生成文字逐字一致。原生读回替代发送前的草稿图像请求；发送后先尝试原生读回，Qt 空编辑框无法复制时，必须用图像确认草稿为空。新气泡和需要复核的草稿尽量合并识别；浅色主题使用实际编辑框分隔线校正识别范围。窗口辅助程序检测聊天和输入区被其他窗口遮挡时，暂停读取和输入并等待恢复，不丢弃进度。发送前的短暂画面变化最多重新校验三次，已输入后的冲突会停止，记录具体失败阶段，不自动重复输入。生成时明确传递本轮新消息，历史仅作为上下文。

个人微信的发言者是账号本人，模型只负责代写。默认规则用简短日常口语，不强行共情、暧昧或每次追问；称呼、关系和个人事实以已提供资料为准。建议在回复规则中补充本人的城市、常用称呼及允许代答的安排，缺少必要事实或涉及本人决定时交给本人回复。历史里错误的 AI 自我描述不会作为身份依据。生成结果出现“我是虚拟助手”“没有真实身体”等表述时，发送前重写一次，仍不合格则拦截暂停；知识库兜底和直接发送也经过该检查。不因正常讨论 AI 技术而拦截，也不会虚构否认工具协助。

回复参考连接后核验为本人手动发送的短句，或在“表情图片与本人用词”中明确保存的样本。程序生成内容按持久化摘要排除，首次看到的旧外发记录不会直接认作本人样本。每个联系人独立学习，可手动添加通用样本；支持关闭、修改、回滚和删除，重启后保留。复用现有 LearningStore 的证据与版本机制，提示词最多取 10 条、1200 字，样本只用于语气，不作为本人事实或承诺。样本不足时采用简短日常表达，减少固定语气词、表情和机械追问。涉及本人的未确认决定时交给本人。

回复可按语义分成 1–3 条气泡，每条确认发送后保存进度，重启只继续尚未发送的部分。收到新消息或本人接话会取消旧计划剩余部分。界面可导入 PNG/JPEG 静态表情图片（最多 4 MB、原始边长不超过 2048，发送尺寸不超过 512）；模型只选择已启用素材的 ID，最多一张，设有全局及联系人冷却。GIF 动图和微信收藏表情尚不支持。图片必须核对目标、草稿与发送回显，结果不明确时不重发。

批量模式的模型生成最多并行两个请求，实际输入和发送始终串行；一个联系人等待生成时会轮到其他联系人。首次只看到小红点且没有保存的进度时，无法证明旧消息的未读数量：仅自动处理预览对应的最新一条，之前连续来信显示为待本人处理。图片、语音等无法解读的来信也保留待处理记录，后续文字仍可继续回复。

回复长度随内容变化，可用几句话回应多个事项，不强制每次一句话或加结尾句号；偶尔使用贴切 emoji，发送前仍逐字核对。模型返回无效 Unicode 字符时保留待处理消息并重试，防止乱码草稿进入聊天。

浅色主题的标题下沿也以实际分隔线校正，避免裁切的旧气泡进入联系人标题锚点。已核对草稿的整块像素、窗口和配置完全相同时，普通监听可复用草稿识别；像素改变后重新读取，独立恢复及发送核验仍保持新证据检查。

## 项目结构和清理

- `src/core/agent/foreground-wechat.ts`：个人回复状态与发送保护。
- `src/main/services/foreground-wechat-driver.ts`：截图识别、模型请求、输入和回显核对。
- `src/core/persistence/foreground-journal.ts`：SQLite 处理进度、发送记录与人工核对。
- `src/renderer`：桌面界面；`native`：Windows 辅助程序。
- `server`：独立企业服务；`tests`：功能与失败场景验证。

Python 情感训练、闲置的 Provider/模拟设备、离线界面样稿和失效测试入口已移除。旧设置中的兼容字段仍可读取。个人自动回复不依赖 Python、PostgreSQL或企业服务启动。

构建成功后自动清理历史产物，保留最近两个成功版本、当前引用版本和近期诊断。也可以先预览再执行：

```powershell
npm run clean:artifacts
npm run clean:artifacts -- --apply
```

清理只针对项目内白名单中的历史构建、原生程序旧版本和生成测试资料；保留源码、依赖、工具链、实际用户资料、数据库和个人微信实机报告，不沿目录联接访问外部文件。详细清理清单位于 `.local/reports/artifact-cleanup`。
