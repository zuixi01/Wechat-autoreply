# 个人微信批量回复

主页默认使用单联系人自动回复。先完成单联系人验证，再展开“多联系人批量自动回复”，每行填写一个允许回复的完整联系人备注名，最多 500 个；名单保存在当前项目用户配置中。选择支持截图的视觉模型、回复模型并保存规则后，点击“启动批量自动回复”。

程序绑定唯一微信进程，在普通聊天列表中确认顶部、滚动并保留重叠行，确认底部后筛选名单中的未读会话。跨页同名目标会被隔离；列表重排或摘要变化会重新扫描。没有确认列表完整性时不会执行批量发送。单轮上限 200 次列表截图、10,000 行，达到上限明确停止，不显示已覆盖全部。遍历的是当前客户端聊天列表，不包括已删除、被隐藏或尚未出现在列表中的联系人。

初次处理未读会话时，核对完整聊天标题、单聊、空草稿、未读数量和末条消息摘要，仅将对应的完整入站文字作为待处理消息。无法对应的数量、仅红点、超过 80 条或截断/非文字消息需要人工核对。启动会处理授权名单中的现有未读消息，页面明确说明这一行为。后续处理保留各会话的独立基线，生成期间的新消息使旧草稿失效并保留任务。

当前打开的授权聊天即使没有未读数字也持续检查：先建立历史基线，再通过完整消息序列判断新增文字。同文字连续来信按序列分别处理，不以摘要或红点作为消息去重依据。

一个桌面只运行一个物理工作循环，依次切换会话、生成、复读及发送。联系人默认使用主页通用回复规则，配置了对象规则时使用该对象策略、模型与知识库。批量模式与单联系人模式互斥，启动一个会先停止另一个。人工暂停、锁屏、休眠和退出会取消在途操作；切换到其他应用只进入等待，不抢回前台，返回微信后再验证。姓名、截图和坐标没有被伪装成原生客户/消息 ID。

SQLite 在打开聊天前保存未读提示，在读取通过后保存待处理会话基线与回复状态。打开聊天消除未读标记后，暂停或应用重启仍可在原实例和配置通过检查时继续未完成任务；窗口实例、配置或消息连续性发生变化则停止该目标。重启不会自动启用服务，必须由用户点击启动。已持久化的未知发送阻止整个个人微信服务重启，不重试 Enter；只有正确会话的外发回显和空输入框才确认发送。状态查询优先展示未核对记录及近期记录，未知状态检查覆盖全部历史。

启动会自动关闭图片预览并返回普通聊天导航，不要求用户预先选定某个客户。截断的无关备注不会停止所有目标，可能与授权联系人同名的截断备注仍隔离该目标；只读取可见摘要，不补全隐藏文字。对已验证、窗口实例和配置相同且列表/输入像素完全未变的页面缓存视觉结果，减少重复模型调用；每次导航前仍重新核对当前像素、前台和取消信号。

这是一条个人微信前台截图适配路径，需要专用电脑或接受自动切换聊天。无法证明无干扰后台运行、稳定原生身份或消息完整覆盖，也不解除企业后台运行的能力门禁。企业微信的真实批量适配仍未验证。本功能不等于大规模全天候生产验收完成。
