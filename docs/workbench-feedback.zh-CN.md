# 工作台核对反馈的自动刷新修复

本步骤承接已批准的 D07/D11：员工必须读到操作的确认结果和不确定性。实际编译界面在核对完成后下一次两秒自动轮询会清除提示，专项已用真实 Electron/renderer/preload 和合成 IPC 稳定复现。用户暂缓实机探测，本步骤不读取聊天客户端或调用模型。

Ruling: 操作确认属于这次员工请求；列表轮询只拥有读取快照的反馈，不得清除员工操作结果 — 当前实现把两个生命周期混用 — 保留现有布局和操作权限，只分开读取故障与操作反馈。沿用已授权计划和当前分支，不另建视觉原型或要求重复许可。

修复范围：自动刷新更新列表并消除已经恢复的读取故障；不清除操作成功/失败提示。员工主动点击刷新或发起下一次操作时清除旧操作反馈。读取失败继续显示明确故障并隐藏失效快照，后续读取恢复后清除故障。核对的暂停说明明确为核对当时的结果，避免员工以后启动时旧提示误称当前仍暂停。保留原有请求版本、过期结果拒绝和忙碌互斥，不修改 Sender、发送许可或后台驱动。

验收用现有真实桌面入口：核对成功后观测实际周期轮询，提示仍在；操作失败提示同样保留；主动刷新清除；读取失败后实际轮询恢复且提示消除；整个过程仍暂停，真实聊天读取、消息和模型调用为零。单独专项不能替代完整桌面/安装/平台或业务准确度验收。既有失败报告保留，不能把一次重跑通过当作修复证明。
