# 个人微信能力与验收状态

更新：2026-10-09。个人微信默认使用前台截图模式；企业后台收发需要经过验证的平台适配器。两种模式的验证结论分别记录。

## 个人微信前台模式

已实现单联系人流程：连接明确选定的单聊、建立历史基线、读取新文字、按模型和规则生成、保存 SQLite 发送记录、核对草稿、单次发送、核对外发回显。首次启动忽略历史消息；暂停和程序重启保留进度。用户必须明确点击启动，程序不会随启动自行启用回复。

微信窗口须完整位于主显示器并保持前台。切到其他应用时等待；回来后重新核对会话、消息连续性、配置和草稿。锁屏、睡眠、人工回复、草稿冲突、窗口实例变化和无法确认消息时暂停。

窗口辅助程序校验绑定的 HWND、PID、可执行路径、启动时间和窗口位置，通过整段 Unicode 粘贴保留中文和 emoji；每次快捷键前后核对前台、焦点和进程。辅助程序保存并恢复剪贴板所有受支持格式，图片保留 DIB 数据；不覆盖操作期间用户新复制的内容，不提供发送键命令。发送前两次精确读回编辑框全文，并在第二次读回前保存画面锚点。Electron 主进程在草稿全文、上下文及画面再次验证后才按一次 Enter，并要求正确单聊的外发回显及空草稿。新增气泡和输入框合并识别，减少图像请求。

首轮回显核验失败后，后续核验独立读取全窗口，避免反复沿用错误的气泡识别结果。滚动导致少数历史气泡像素变化且文字识别不一致时，最多对两处差异分别复读发送前后的气泡截图；两次完整原文必须一致，其他历史连续性、消息方向、会话绑定和空输入框仍须通过。复核不会再次输入或发送。

发送结果不确定时保留记录、暂停并阻止重新启动，不重试发送。在微信人工核对后可明确标记结果；核对会重建后续接入起点，不自动重发原消息。近期列表会优先显示未核对记录，未知结果检查覆盖全部历史。

## 能力边界

个人模式依赖视觉读取，尚无原生账号、客户和消息 ID。单联系人一次验收不能证明所有联系人、长期连续运行、断网恢复、同名联系人区分或微信升级后的兼容性。群聊、语音、图片和文件不作为可自动回复的文字消息处理。

[批量模式](personal-wechat-batch.zh-CN.md) 作为展开功能保留，限明确填写的联系人名单。已验证合成容量和失败场景，尚未完成真实微信全列表覆盖和批量回复验收。

后台平台适配器当前没有证明未打开聊天的完整读取或不干扰办公的定向发送。登记设备和原生窗口元数据探测不提供这些能力，也不会解除运行门禁。企业状态见 [企业能力报告](capability-report.wework.md)。
