## 2026-10-04 项目个人微信前台模式

用户已登录微信，明确授权切换窗口和向联系人 Q 测试。新增独立的单联系人前台模式：项目通过构建时固定 SHA-256 摘要校验的窗口辅助定位微信，使用自身 RobotJS 捕获物理窗口截图、输入及单次 Enter；视觉识别与回复使用主页已保存的模型、规则和知识库。首页提供启动、暂停、真实运行阶段、错误原因及 SQLite 持久化回复记录。启动读取建立历史基线，只处理之后的新文字消息。

发送前复读消息，检查聊天标题、草稿、窗口进程实例、屏幕范围及规则版本。最后一次异步窗口检查后同步核对标题/消息/输入像素、取消信号和规则版本，再发送一次；仅观察到正确会话的外发回显及空输入框才标记已发送。未知发送立即停止并阻止重新启动，不重发。主显示器外的窗口、人工输入、切换前台、消息无法接续及锁屏/睡眠均停止。

该模式是项目本身的功能，与企业后台模式分开。它没有原生账号/消息 ID，也没有解决全客户后台读取和不干扰办公；现有后台能力表及三项 false 门禁保持有效。

真实项目首页按钮已经启动过该流程，唯一微信窗口定位及截图路径可运行，但第一条模型请求连接被重置，尚未进入 Q 搜索或发送。已保存模型中转站 router.keenlight.ai 的 Node 请求、Electron 网络请求和系统 TLS 检查均失败。当前没有真实微信自动回复成功记录，需先恢复模型连接，再让 Q 发送启动后的新消息完成收发验收。没有使用助手手动发送消息代替验收。

最终验证：24 项前台运行时、持久化和实际驱动边界专项测试通过；主进程、网页及服务类型检查通过；生产构建、代码检查和隔离桌面冒烟通过。桌面冒烟覆盖个人模式的缺模型提示、私有 IPC 及既有企业流程。只读代码复核确认发送前的输入/规则/取消竞态已修复。正常用户设置下的项目实测状态为 `paused / model_network_failed`，发送记录为零；此结果仍不是自动收发验收通过。

用户要求继续排查后，补充验证了 DNS 与路由：Google 和 Cloudflare DNS 均返回相同实际地址；系统 DNS 为本机代理的虚拟地址。其他 HTTPS 网站可访问，同一中转站使用 TLS 1.2、实际 IP、HTTP/SOCKS 代理仍无法完成握手。只读代理连接元数据确认当前请求走境外节点；其他节点及直接连接的探测也未成功。以上不能单独证明服务端故障，也没有证据表明密钥失效，因为连接尚未进入 HTTP 授权阶段。需要对照官方 Base URL 或当前可正常调用的客户端配置继续诊断。没有切换全局代理节点、修改系统代理/DNS、关闭证书验证或更改模型密钥。

运行入口：开发环境先执行 `npm run publish:foreground`（仓库本地 .NET 工具链），然后 `npm run build`、`npm run start`。首页选择支持图片的视觉模型和文本回复模型，确认模型配置测试通过，填写唯一联系人备注名，再点“启动个人微信自动回复”；保持微信完整显示于主显示器前台。真实验收启动脚本 `scripts/personal-wechat-test.cjs` 使用正常项目设置及项目按钮，仅指定 Q；本地报告只存运行状态和记录状态，不复制聊天原文或密钥。
