# 个人微信能力与验收状态

更新：2026-10-13。个人微信默认使用前台截图模式；企业后台收发需要经过验证的平台适配器。两种模式的验证结论分别记录。

## 个人微信前台模式

已实现单联系人流程：连接明确选定的单聊、建立历史基线、读取新文字、按模型和规则生成、保存 SQLite 发送记录、核对草稿、单次发送、核对外发回显。首次启动忽略历史消息；暂停和程序重启保留进度。用户必须明确点击启动，程序不会随启动自行启用回复。

微信窗口须完整位于主显示器并保持前台。切到其他应用、聊天或输入区被通知遮挡时等待；恢复可见后重新核对会话、消息连续性、配置和草稿。锁屏、睡眠、人工回复、草稿冲突、窗口实例变化和无法确认消息时暂停。

窗口辅助程序校验绑定的 HWND、PID、可执行路径、启动时间和窗口位置，通过整段 Unicode 粘贴保留中文和 emoji；每次快捷键前后核对前台、焦点、进程和可见表面。辅助程序保存并恢复剪贴板所有受支持格式，图片保留 DIB 数据；不覆盖操作期间用户新复制的内容，不提供发送键命令。发送前两次精确读回编辑框全文，并在第二次读回前保存画面锚点。Electron 主进程在草稿全文、上下文及画面再次验证后才按一次 Enter，并要求正确单聊的外发回显及空草稿。发送后先尝试原生读回；Qt 空编辑框无法复制时，必须回到图像核对草稿为空。新气泡和草稿可合并识别；浅色主题从实际编辑框分隔线校正正文范围，避免模型矩形误差遗漏底部回复。图像字段无法识别时不猜测内容。

首轮回显核验失败后，后续核验独立读取全窗口，避免反复沿用错误的气泡识别结果。滚动导致少数历史气泡像素变化且文字识别不一致时，最多对两处差异分别复读发送前后的气泡截图；两次完整原文必须一致，其他历史连续性、消息方向、会话绑定和空输入框仍须通过。复核不会再次输入或发送。

文件卡片滚动后的像素变化另行核对：发送前后每个卡片的完整文件名、扩展名、显示大小及单位必须分别读出并完全一致，气泡数量、方向和顺序相同，且存在完整原始画面中唯一的原生文字锚点。不能用通用“非文本消息”占位符证明一致。核验成功后保存已验证的历史前缀，排除本次外发回显和随后新消息，供继续监听使用。普通新消息导致的媒体变化只有保留对应截图证据时才能同样恢复；重启后缺少原截图仍可能需要本人核对。

已发送但暂时无法核对回显时保留未知记录，持续独立复查，期间不生成、输入或发送下一条；确认后更新同一记录并继续处理后续新消息。人工草稿、会话冲突等仍暂停。程序退出后未核对记录阻止重新启动；在微信人工核对后可明确标记结果，不自动重发原消息。近期列表会优先显示未核对记录，未知结果检查覆盖全部历史。读取、连接与生成时的暂时接口故障持续等待恢复，重试间隔最多 30 秒。

回复表达优先参考本人手动外发的短句，排除本地程序生成记录、身份说明及只有表情识别差异的旧程序回复。样本不足时使用简短日常表达，减少固定表情、语气词和机械追问。身份约束是内部规则，不允许把“我是这个微信账号的本人”等程序说明发给对方；必要个人事实不足仍交给本人处理。

## 能力边界

2026-10-13，构建 `5cc06459-1e3c-4da2-8289-7c2bf018c663` 的完整 217 文件、2638 项测试与 Windows 构建、包内组件、桌面启动及独立目录冷启动通过，源文件与程序包哈希一致。实机视觉返回格式有效，但仍有约 17–35 秒读取；授权测试联系人 A 的旧动态表情使输入前精确画面检查拒绝，记录为 `not_sent / before_input / send_screen_changed`，未输入或按发送键，双联系人连续验收尚未通过，桌面入口未切换。

后续最小修复将输入前画面拒绝次数与接口恢复次数分离，防止此前模型超时提前耗尽三次画面恢复预算。精确画面采样改为不同间隔，仍保留 4.5 秒、40 次双上限及原始完整像素比较，不屏蔽动画、不改回显锚点、不重复粘贴。周期采样回归先失败后通过；这些调整不能保证持续动画必有可匹配帧，必须在新构建中重新实测，不能算作动态表情问题已解决。

2026-10-13，上一版完整测试 217 文件、2622 项通过。实机发现视觉供应商有时返回 `point/label` 等其他格式及像素单位，导致定位失败；列表在识别等待中实际发生重排，导航检查拒绝点击后又重新执行整个名单核对。修复在视觉系统提示中明确嵌入输出格式；搜索、导航和列表的格式错误最多对同一截图重新读取一次，仍使用原有严格本地验证，不转换字段或猜测坐标。聊天读取保留原有独立重试和原生草稿读回，避免重复重试。

导航帧过期时，已建立消息基线的任务保留队列，但所有联系人目录证明失效；下一轮对将要打开的联系人重新执行完整唯一性核对，失败时不进入聊天或发送。尚无消息基线的排队联系人还须刷新未读数和预览，避免遗漏等待期间追加的消息。存在待确认发送时优先复查原回执，不轮转启动新的发送；对象无法确认则停止并保留未知记录。所有点击前的精确画面、对象绑定、人工草稿和发送回显检查保留。新增回归先复现失败后验证通过；当前补丁的完整测试及双联系人连续实机验收仍须单独确认，不能沿用上一版的通过结论。

逐联系人唯一性核对出现暂时接口错误时，保留其失效标记并让其他排队任务获得处理机会，避免尚未创建会话的慢任务永久阻塞队列；有待确认回执时不启用这一轮转。

已有待处理提示、但首次读取失败且从未建立基线的会话，无法用清零或新增后的徽标证明累计待答范围。恢复使用显式持久化的范围未知状态，仅自动处理预览锚定的最新项，较早连续入站保存为 `unread_boundary_ambiguous` 待人工确认；不伪造红点、不相加未读数、不把这些消息静默并入历史。普通无未读的首次基线读取失败不触发历史回复。相关批量与 SQLite 两文件 59 项隔离测试通过，包括同预览重复入站、徽标清零、跨重启不重发以及预览不匹配暂停后的恢复；仍须新的完整测试与真实连续收发验收。

2026-10-12 超时排查：同一张已保存截图的旧接口请求 55 秒超时；关闭截图提取的额外推理后两次返回完整 JSON，约 17.8 秒、14.3 秒。严格 JSON Schema 的真实接口探测通过，约 21.6 秒。以上只是识别接口样本，不能等同完整回复耗时。此前源码完整测试 217 文件、2557 项通过；后续结构化输出、队列调度及媒体边界修复须以新的最终测试报告为准。

2026-10-12 21:31，最终运行时代码完整测试 217 文件、2592 项通过，保持原有测试时限；Windows 构建、包内组件、桌面界面及独立目录副本首次冷启动通过。实机确认一次三个文件卡片变化后的自动发送回显恢复，约 168.8 秒；另一个旧外发记录由人工核对后标记，不能计作自动验收。新接口兼容处理支持单个对象的数组包装，并在严格结构化请求返回空数组或原样返回格式定义时一次切换 JSON 对象格式，后续结果仍严格校验。短回复关闭额外推理，避免输出额度全部用于隐藏推理而没有正文。

最终双联系人验收未通过：当前接口的两个可用模型仍出现约 35–45 秒识图及超时，且列表范围识别不准、画面变化可导致导航重试，已生成的回复可能等待发送。实机没有证明最终版本两位联系人连续三轮收发稳定。已保存待处理消息和发送记录，没有重置进度或重发已确认内容；需要继续解决视觉读取的可靠性和时延，不能把程序持续重试视为稳定回复。

后续发送诊断发现标题未变而正文动画区域变化，导致粘贴后的单次画面校验拒发。文字和图片发送改为有界等待原始像素恢复，每个检查点最多 4.5 秒、40 次；不屏蔽动画区域、不接受近似相同画面。文字等待后再次原生读回草稿，图片仍须完整草稿与历史连续性证明；图片输入框扩高后也保留原草稿锚点。持续变化、人工改稿、窗口或规则变化仍停止发送，不能将此补丁视为双联系人实机验收通过。

个人模式依赖视觉读取，尚无原生账号、客户和消息 ID。单联系人一次验收不能证明所有联系人、长期连续运行、断网恢复、同名联系人区分或微信升级后的兼容性。群聊、语音、图片和文件不作为可自动回复的文字消息处理。
